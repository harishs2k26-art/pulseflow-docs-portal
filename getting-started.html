Quickstart / approximately 10 minutes

Your first observable workflow

Start small: one workspace, one workflow and one event. Prove correlation and redaction before instrumenting an entire application.

All commands below describe a fictional API contract. The reserved .example hostname is not a working service. For something runnable without credentials, open the local SDK playground.

1. Prepare a development workspace

In the imagined control plane, create ws_demo in us-east-1 and label it environment=development. Assign a service owner and a retention policy. Keep staging and production in different workspaces so quotas and access boundaries can be tested independently.

  • Use UTC clocks synchronized within five minutes.
  • Choose a stable workflow name such as checkout.fulfillment.
  • Decide which fields must be removed: authorization headers, cookies, addresses and payment details are not telemetry.

2. Configure least-privilege access

# Illustrative environment variables; never commit a real token.
export PULSEFLOW_WORKSPACE=ws_demo
export PULSEFLOW_REGION=us-east-1
export PULSEFLOW_TOKEN=pf_test_REPLACE_ME

A producer only needs events:write. Give a separate diagnostic identity traces:read if necessary. Do not reuse an administrator token in a browser, workflow log or shared shell profile. In a real deployment, inject secrets from a secret manager.

3. Describe an event

# Illustrative request: this endpoint intentionally does not operate.
curl --request POST 'https://api.pulseflow.example/v1/events' \
  --header "Authorization: Bearer $PULSEFLOW_TOKEN" \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: checkout-demo-42' \
  --data '{"id":"evt_demo_1001","type":"workflow.succeeded","schema_version":"2026-10-01","occurred_at":"2026-11-14T07:00:00Z","workspace_id":"ws_demo","data":{"run_id":"run_checkout_42","duration_ms":184}}'

The imagined API responds 202 Accepted with a request ID and accepted count. Reusing the same idempotency key and identical body within 24 hours returns the original acceptance result. A key reused with a different body is a conflict, not a second event.

4. Validate the result

5. Establish safe operational limits

The demo contract caps a single envelope at 256 KiB and a batch at 100 events or 1 MiB, whichever comes first. A producer flushes every two seconds, bounds its local queue and backs off on 429 responses. Use exponential backoff with jitter for transient failures; do not retry malformed payloads indefinitely.

Before promoting to production

  • Exercise token rotation and revoke the development token.
  • Verify that logs contain request IDs but no credentials or raw personal data.
  • Replay a duplicate event and confirm downstream idempotency.
  • Confirm retention, residency and alert ownership with the team.
